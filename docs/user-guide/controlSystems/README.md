# Control Systems

The Control Systems module is the **bulk generator and registry of system codes** for the facility's control hierarchy. Where the [System Hierarchy](../systemHierarchy/README.md) detail page lets you generate a system code for *one* system at a time, this module lets you mint a *batch* of codes against a given **Zone + System Type** combination in one operation and review every system code that has ever been generated in a single, filterable table.

Use this module when commissioning a new zone (you need ten consecutive control-system codes for an upcoming installation), when planning labels ahead of physical receipt, or when auditing which codes have been generated against a zone / type.

## Access & Responsibilities

**Today's reality:**
- `control-systems-view` — read-only access to the **Overview** page. Filter, search, and inspect existing system codes. The *Create System Codes* button is hidden.
- `control-systems-edit` — full edit. View the Overview and access the dedicated **Create System Codes** page; submit a batch creation.
- `admin` — same as Editor.

**Personas (today):**

| Persona | Role(s) | Can do |
|---|---|---|
| 👁️ **Viewer** | `control-systems-view` | Open the Overview, filter and search the system-codes table, click into a row to view the underlying system detail |
| ✏️ **Control-Systems Editor / Admin** | `control-systems-edit` or `admin` | Everything in Viewer + open the Create System Codes page, pick a Zone + System Type + Batch count, preview the codes that will be generated, submit the batch |

> 🔮 **Coming soon — zone-scoped permissions** — a planned enhancement will restrict batch creation to the zones a user is responsible for; today both roles are facility-wide.

## Key concepts

- **System code** — the short identifier on a system that uniquely names it within the facility (e.g. `IONB-001`). Generated by combining the System Type's *code* and *mask* with the zone code and a serial number.
- **Zone (root)** — the *root* zones from the Zone codebook are the only ones eligible as a target for batch creation. Sub-zones are not surfaced here.
- **System Type** — the classification of system the codes are being generated for. The type's *mask* (set in [System Type Edit](../systemTypeEdit/README.md)) determines how the code string is composed.
- **Batch count** — how many consecutive codes to generate in one submission. UI cap: **1–25** per submission.
- **Preview** — a live, debounced render of the codes that *would* be generated for the current Zone + System Type + Batch tuple. No state is created on the server during preview; submission is what commits them.
- **Created** — codes that have been committed in the current session. They appear above the preview rows in the right pane on the Create page, badged *Created*, and link to the system detail page.

## Layout

The module has **two surfaces**: the Overview and the Create page.

### Overview page (`/control-systems/overview`)

A sticky-header explorer for every system code generated against any zone / type.

- **Sticky header.**
  - **Search field** with pattern detection. Three patterns are recognised: `C01` (starts-with), `*C01*` (contains), `*C01` (ends-with). Hover the help icon for the tooltip.
  - **Zone** filter (picker).
  - **System Type** filter (picker).
  - **Filter badges** for each active filter; per-chip clear.
  - **Column visibility** dropdown on the right.
  - ***Create System Codes*** button on the far right (visible only with `control-systems-edit`); navigates to the Create page.
- **Table.** Columns: *System Code*, *Name*, *Location*, *Zone*, *System Type*, *Path* (parent path of the linked system), *Updated By*, *Created By*. 50 rows per page. Row click opens the underlying system detail in an edit sheet; row hover surfaces a per-row action menu (*Edit System*, *Delete System*).

### Create page (`/control-systems/system-codes-create`)

A dedicated two-pane workbench, gated by `control-systems-edit`.

- **Left pane — Form (380 px).**
  - *Zone* combobox (root zones only).
  - *System Type* combobox.
  - *Batch Count* spinner (± controls plus an input; range 1–25). Placeholder reads *Number of system codes to create*.
  - *Create System Codes* button.
- **Right pane — Preview / created table (flex-1).** Two visual bands:
  - **Created** rows on top, badge *Created*, each *System Code* clickable to open the corresponding system detail in a new tab. These persist for the current session as you continue to create more batches.
  - **Preview** rows below, badge *Preview*, dimmed. Live-debounced render of what the next submission would generate.
  - Empty state: *No preview available* / *Fill in the form to preview system codes that will be created.*

## Data model reference

> 🔧 *This section is for engineers reading the docs in the repo. The Confluence generator strips it.*
>
> Endpoints: `GET /systems/system-codes` (overview, key `systemCodes`), `GET /systems/system-codes/preview` (preview, key `systemCodesPreview`, query params `zoneUid`, `systemTypeUid`, `batch`), `POST /systems/system-codes` (commit, key `systemCodesCreate`). UI batch cap is 25 (enforced in `types/constants.ts` as `BATCH_LIMIT`); Zod schema allows up to 100. Code-string composition uses the System Type's mask — see `src/modules/systemHierarchy/components/SystemCodeActions.comp.tsx` for the per-system generation path. Root-zone filter constant: `ONLY_ROOT_ZONES`.
